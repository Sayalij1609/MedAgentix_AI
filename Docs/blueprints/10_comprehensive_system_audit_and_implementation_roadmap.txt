2. Architectural Blueprint for Document-Augmented Medical RAG:

   ```
   ┌────────────────────────────────────────────────────────────────────────┐
   │                            USER QUERY                                  │
   │  "What does high alkaline phosphatase mean in my uploaded lab report?" │
   └───────────────────────────────────┬────────────────────────────────────┘
                                       │
            ┌──────────────────────────┴──────────────────────────┐
            ▼                                                     ▼
   ┌─────────────────────────────────┐   ┌─────────────────────────────────┐
   │    DOCUMENT RETRIEVAL CONTEXT   │   │    GLOBAL MEDICAL KNOWLEDGE     │
   │  (User-Uploaded Lab/Doc Chunks) │   │  (PubMedBERT / Medical KB CSV)  │
   │  • Parsed via OCR / PyMuPDF     │   │  • Pre-indexed in FAISS Vector  │
   │  • Specific to patient report   │   │  • Guidelines, drugs, diseases  │
   └────────────────┬────────────────┘   └────────────────┬────────────────┘
                    │                                     │
                    └──────────────────┬──────────────────┘
                                       ▼
   ┌────────────────────────────────────────────────────────────────────────┐
   │                     HYBRID RETRIEVAL & AUGMENTER                       │
   │  • Ranks and combines top document chunks + top medical KB chunks      │
   │  • Constructs prompt with clear source attribution:                     │
   │    [Source 1: Patient Lab Report (Uploaded Doc)]                       │
   │    [Source 2: Clinical Practice Guidelines (Knowledge Base)]           │
   └───────────────────────────────────┬────────────────────────────────────┘
                                       ▼
   ┌────────────────────────────────────────────────────────────────────────┐
   │                           GENERATOR / LLM                              │
   │  • Primary: Google Gemini / Groq Llama-3-70B Medical                   │
   │  • Fallback: Clinical Template Engine                                  │
   │  • Output: Evidence-grounded answer with source citations & warnings   │
   └────────────────────────────────────────────────────────────────────────┘
   ```

3. Components to Implement:

   A. `agents/rag_agent.py` (Master Agent):
      - Methods:
        - `query(question: str, session_id: str = None, top_k: int = 4) -> dict`
        - `query_with_document(question: str, document_text: str, top_k: int = 3) -> dict`
        - `attach_document(session_id: str, file_path: str) -> dict`

   B. Dual-Index Retrieval:
      - Ephemeral Document Index: When a patient or doctor uploads a PDF or image, it is parsed
        by `OCRAgent` / `fitz`, chunked into 300-token snippets, embedded, and stored in a
        per-session FAISS index.
      - Global Medical Index: Pre-computed FAISS index from `Medical Knowledge Dataset.csv` (1,000+
        vetted clinical chunks).

   C. Chatbot Document Upload API:
      - `POST /api/v1/chatbot/upload-doc`
        Accepts: `multipart/form-data` with `file` and optional `session_id`.
        Returns: Document summary, extracted test entities, and `session_id`.
      - `POST /api/v1/chatbot`
        Body: `{ "message": "...", "session_id": "..." }`
        If a document is attached to `session_id`, the agent performs dual retrieval across both
        the document and the medical knowledge base.

================================================================================

1. Current State:
   - `xai/shap_explainer.py` exists (14 KB) and generates SHAP feature contributions and bar plots.
   - `xai/lime_explainer.py` is 0 bytes (empty).
   - `agents/xai_agent.py` is 0 bytes (empty).
   - Currently, there is no separation between doctor-facing XAI and patient-facing XAI.

2. Strict Visibility Boundary: DOCTOR vs. PATIENT

   CRITICAL CLINICAL REQUIREMENT:
   Technical feature-attribution graphs (SHAP force plots, LIME regression weights, negative
   attribution values, raw diagnostic probabilities) must ONLY be displayed on the Doctor
   dashboard (`pages/doctor/assessment.tsx`).

   - DOCTOR DASHBOARD (Technical XAI View):
     1. SHAP Feature Importance Waterfall / Bar Chart (PNG rendered or interactive Chart.js).
     2. LIME Local Explanation Weights (showing top 5 supporting and top 3 contradicting features).
     3. Cross-Explanation Concordance Score:
        `Concordance = (Overlapping Top-3 Features between SHAP & LIME) / 3 * 100%`
     4. Raw model probabilities, entropy, and calibration status.

   - PATIENT DASHBOARD (Clinical Narrative View):
     1. Natural language explanation strictly focused on understandable symptoms:
        "Your elevated body temperature and persistent cough were the primary indicators for this assessment."
     2. NO intimidating negative numbers (e.g., "Feature -0.42 log-odds").
     3. NO confusing machine learning terms (TreeExplainer, perturbations, Ridge weights).
     4. Clear next-step guidance: "What this means for you" and "When to consult a physician."

3. Implementation Details:

   A. `xai/lime_explainer.py`:
      - Uses `lime.lime_tabular.LimeTabularExplainer`.
      - Wraps the XGBoost / Ensemble model.
      - Generates local feature weights for the predicted disease class.

   B. `agents/xai_agent.py`:
      - Orchestrates both SHAP and LIME.
      - Calculates the agreement metric:
        - If SHAP and LIME agree on top features: `Reliability: HIGH (Verified by multi-algorithm XAI)`
        - If they diverge: `Reliability: MODERATE (Physician review strongly recommended)`
      - Produces two separate payloads in its output:
        - `doctor_xai`: Contains `shap_plot_path`, `shap_values`, `lime_values`, `concordance_score`.
        - `patient_xai`: Contains `simplified_summary`, `key_symptoms_identified`, `lifestyle_factors`.
